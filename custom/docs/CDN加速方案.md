## 一、实测数据：一局游戏到底下载多少

| 阶段 | 请求数 | 传输字节 | 主要构成 |
|---|---|---|---|
| A 首屏（登录页） | 152 | 2.39 MB | Google Fonts 0.94 MB、ui 贴图 0.40 MB、js 0.49 MB |
| B 大厅（点「开始」后） | 8 | 2.24 MB | **BGM 单文件 2.18 MB** |
| C 房间 + 干员调配 | 13 | 0.48 MB | 干员图标 |
| D 进入对局加载 | 365 | 3.52 MB | char 立绘 1.83 MB、bond 23 个、其余 299 个小文件 |
| E 对局内 +25 s | 1 | ~0 | 已预热完毕 |
| **合计** | **539** | **8.64 MB** | |

### 三个关键结论

1. **字节不多（8.64 MB），请求极多（539 个）** → 平均每个文件只有 16 KB。
   瓶颈不是带宽总量，而是「**请求数 × 单请求延迟**」。CDN 的价值主要在于把每一次往返拉近到玩家身边。
2. **同源请求中位耗时 554 ms、最慢 1086 ms**（`/healthz` 460 字节也要 1086 ms）。
   注意：该绝对值含本机链路的固定开销，玩家侧应以 RTT 为准；但「小文件也接近 1 秒」这一形态是真实的。
3. **首屏 2.39 MB 里有 0.94 MB / 17 个请求来自 Google Fonts**，跨境外链：
   - `fonts.googleapis.com/css2?...Noto+Sans+SC...` → 返回 **412 个 @font-face 子集、452 KB**（gzip 后 119 KB）
   - 浏览器按 unicode-range 只下载用到的约 16 片子集（`fonts.gstatic.com` 的 woff2，约 0.82 MB）
   - 这是**唯一一处跨境依赖**，也是「有时候字体/资源出不来」的高概率元凶

## 三、第 1 步：Google Fonts 自托管（0 成本，收益最大）

**现状**（`public/index.html:21-24`）：

```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link rel="stylesheet"
      href="https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@400;500;700;900&family=Oxanium:wght@400;500;600;700&family=Rajdhani:wght@500;600;700&display=swap" />
```

**为什么这是最大痛点**：国内访问 `fonts.gstatic.com` 受国际出口影响，延迟抖动大、偶发超时。字体请求挂在渲染路径上，会连带拖慢首屏观感（用户描述「经常加载不出声音或者图片」，字体外链是很可能的共因）。

**做法（两条路线，建议先 A 后 B）**：

- **A. 原样自托管（改动最小）**
  1. 下载上述 CSS + 全部 412 个 woff2 到 `public/assets/fonts/`（磁盘约 8–10 MB）
  2. 把 CSS 里的 `https://fonts.gstatic.com/...` 批量替换为 `/assets/fonts/...`
  3. `index.html` 的 `<link>` 改为 `<link rel="stylesheet" href="/assets/fonts/fonts.css">`
  4. 删掉两行 `preconnect`
  - 效果：仍然是「按需下载约 16 个子集」，但**全部同源/走 CDN，零跨境**

- **B. 精简子集（可选，进一步瘦身）**
  用 `fonttools pyftsubset` 把 Noto Sans SC 裁到游戏实际用到的几百个汉字 → 单个 woff2 约 100–200 KB。
  代价：新增字形时要重新生成，维护成本上升。**非必要不做。**

## 四、第 2 步：CDN 选型与购买

### 4.1 选 CDN 还是 EdgeOne？

| | 腾讯云 CDN | 腾讯云 EdgeOne |
|---|---|---|
| 定位 | 纯静态/动态加速 | 加速 + 安全（WAF / DDoS / 智能路由） |
| 计费 | 按流量或带宽，**支持流量包抵扣** | 套餐制（含免费档，有流量/带宽上限） |
| 成本 | 最低 | 更高 |
| 适合 | **本案**：同人作品、无变现、无被攻击风险 | 需要防刷 / 有商业流量 |

**结论：用腾讯云 CDN 就够**，不用上 EdgeOne。

### 4.2 计费方式怎么选

**选「按流量计费」+ 提前买流量包**（不要选按带宽）。

理由：按带宽计费按日峰值 × 单价，且**不支持流量包抵扣**；本项目流量极小且集中在开局瞬间，按流量更省。

**中国境内参考价**：

| 流量包 500 GB | ≈ ¥88 – 108 |

### 4.3 接入方式（推荐：整域接入，零代码改动）

游戏内所有资源都是相对路径（`/assets/...`、`/media/...`），所以**直接把加速域名设成 `sp.example.com` 就能生效，不用改一行代码**。

**控制台配置清单**：

| 配置项 | 值 |
|---|---|
| 加速域名 | `sp.example.com`（已备案，可直接用） |
| 业务类型 | 静态加速 |
| 源站类型 | 自有源 / IP |
| 回源地址 | `<源站IP>:80` |
| 回源协议 | HTTP（源站已由 certbot 管证书，回源无需再加密） |
| 计费方式 | 按流量 |

**缓存规则**（按优先级从上到下）：

| 路径 | 缓存时间 | 说明 |
|---|---|---|
| `/assets/*` | 30 天 | 素材是版本化的静态资源，可长缓存 |
| `/media/*` | 30 天 | BGM / 音效，单局最大项 2.18 MB |
| `/js/*`、`/css/*`、`/shared/*` | 1 天 | 无构建版本号，别设太长，免得改代码后不生效 |
| `/`、`/healthz` | 不缓存 | 源站已返回 `cache-control: no-cache` |
| `/ws` | 不缓存 + **开启 WebSocket** | 对局长连接 |

**建议同时开启**：

- HTTP/2（源站已开，CDN 侧也开）
- Brotli / Gzip 压缩 —— `.atlas` / `.json` / `.skel` 压缩收益明显
- 「忽略参数缓存」—— 素材 URL 无 query，可减少回源
- Range 回源 —— 音频拖动需要
- 证书：腾讯云免费 DV 证书（域名在 DNSPod，签发最省事）

**可选**：Referer 防盗链白名单。同人作品不宜公开传播，这能顺手挡掉外站盗链。

### 4.4 与已完成 P0 的关系

- nginx 直出 `/assets/` **继续保留**：CDN 回源时命中 nginx，不经过 Node，源站开销更小
- 源站 3 Mbps 管道：接入 CDN 后**只有「边缘未命中时的回源」走它**，玩家侧不再受这 3 Mbps 限制
- 副作用提示：CDN 首次缓存未命中时，仍需从源站拉一次（受 3 Mbps 限制），但命中后全员共享

## 五、风险与注意事项

1. **备案**：CDN 加速域名必须备案 —— `example.com` 已备案 ✅
2. **WebSocket 走 CDN 的取舍**：会额外计费（0.20 元/万次）且多一跳延迟。
   若发现对局内延迟变差，可改为**只让 `/ws` 直连源站**（需改前端一处连接地址），静态资源仍走 CDN。
   建议：**先整域接入，实测对局延迟；有问题再拆。**
3. **`/media/*` 无扩展名**：源站是靠 Node 按 `.mp3/.ogg/.m4a` 顺序查找的虚拟路由（`server/http/media.js`）。
   接入 CDN 后 `/media/*` 会回源到 Node；若要进一步优化，可在 nginx 加 `try_files` 直出（见第六节第 3 项）。
4. **别囤流量包**：非商业同人作品，¥20 档足够。
5. **CDN 不会解决 Google Fonts 问题**：字体在境外，CDN 无法加速 Google 的服务器。必须先做第 1 步。
