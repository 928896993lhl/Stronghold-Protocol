# 对局内语音消息 —— 实现方案

> 目标：在联机对局中让队友互发短语音（按住说话，最长 8 秒），而不是实时语音通话。
> 基线：**服务器当前版本 v0.2.2**。文中行号均以该版本为准（已逐条 grep 核实）。
> 性质：官方设计明确 `Communication is emotes only. There is no text chat.`，语音属**定制功能**，
> 与「阵营许愿」同属第二层改动，会被官方 update 包覆盖，需走 patch 流程（见第 6 节）。

---

## 0. 为什么是「语音消息」而不是「实时通话」

| | 语音消息（本方案） | 实时语音通话 |
|---|---|---|
| 技术 | MediaRecorder + 现有 WebSocket 转发 | WebRTC + STUN/TURN |
| 服务器改动 | 约 7 个文件，完整照抄表情链路 | 新增 coturn 服务、开 UDP 端口段 |
| 带宽 | 单条约 32 KB，发完即止 | 持续 30–50 kbps/人，全程占用 |
| 国内网络 | 走现有 HTTPS/WSS，无障碍 | P2P 常打不通，必须 TURN 中继，流量全过服务器 |
| 观战/回放 | 可留存 | 无法留存 |

该机此前实测首页加载 5.2 秒属**带宽瓶颈**，实时通话会让 4 人房间长期吃满上行。且战斗模拟跑在各浏览器本地
（`SP_COMBAT=client`），语音只做转发、不进模拟，不会引入确定性或校验风险 —— 这是语音消息方案最大的优势。

## 1. 现状：可直接复用的表情链路

| 环节 | 位置（v0.2.2） | 内容 |
|---|---|---|
| 协议白名单 | `shared/protocol.js` `'g.emote': { id: (v) => EMOTES.includes(v) }` | C2S 校验 |
| 下行白名单 | `shared/protocol.js` S2C 数组 | 含 `'m.emote'` |
| 冷却常量 | `shared/constants.js:241` | `EMOTE_COOLDOWN_MS = 1000` |
| 服务端处理 | `server/match/match/intents.js:52` | `emote(ps, id)` → `this.broadcast({ t: 'm.emote', playerId, id })` |
| 座位状态字段 | `server/match/PlayerState.js` | `this.lastEmoteAt = -Infinity` |
| 前端动作 | `public/js/ui/gameActions.js:69` | `emote: (id) => act('g.emote', { id }, { quiet: true })` |
| 前端接收 | `public/js/main.js:248` | `net.on('m.emote', …)` → 写入 store |
| store 字段 | `public/js/store.js:84` | `emotes: []` |
| 界面控件 | `public/js/screens/game.js:1463` | `<${EmoteWheel} … onSend=${(id) => actions.emote(id)} />` |

**`g.voice` 应当与 `g.emote` 完全同构。** 下面每一处都是「照抄 + 换字段名」。

### 已确认的两个硬约束

1. **载荷上限 64 KB** — `server/http/websocket.js:16` `WS_MAX_PAYLOAD = 64 * 1024`，超限连接直接被拒。
2. **服务器拒绝二进制帧** — `server/net.js:589` 收到 `isBinary` 直接回 `BAD_MSG`（`'binary frame'`）。
   所以音频只能 base64 成字符串随 JSON 发送。改造 `onFrame` 支持二进制要动编码分派，不值得。

### 体积核算（8 秒方案）

```
8 s × 24 kbps = 24 KB 音频 → base64 后约 32 KB → 远低于 64 KB 上限 ✅
```
结论：**8 秒上限不需要动 `WS_MAX_PAYLOAD`。** 若将来想放宽到 15 秒，必须把它提到 `256 * 1024`。

## 2. 改动清单

### 2.1 `shared/constants.js`（约 241 行后）

```js
// 对局内语音消息 (remake option): 8 s keeps a base64 frame (~32 KB) well under WS_MAX_PAYLOAD (64 KB).
// NOTE: audio.js already exports VOICE_COOLDOWN_MS (干员语音冷却) — the VOICE_MSG_* prefix avoids the clash.
export const VOICE_MSG_MAX_MS = 8000;
export const VOICE_MSG_MIN_MS = 300;
export const VOICE_MSG_MAX_B64 = 40 * 1024; // base64 chars ≈ 30 KB of audio
export const VOICE_MSG_COOLDOWN_MS = 8000;
/** Containers MediaRecorder may produce: Chrome/Firefox → webm/opus, iOS Safari → mp4/AAC. */
export const VOICE_MSG_MIMES = Object.freeze(['audio/webm', 'audio/mp4', 'audio/ogg', 'audio/mpeg']);
```

> ⚠️ **命名坑**：`public/js/audio.js` 里已存在 `VOICE_COOLDOWN_MS`（干员语音冷却，与玩家语音无关）。
> 必须用 `VOICE_MSG_*` 前缀，否则同名导入会让读代码的人误判语义。

### 2.2 `shared/protocol.js`

导入上面的常量，然后：

```js
// 对局内语音消息 (remake option): a short recorded clip, relayed to the room like an emote.
const isVoiceData = (v) => typeof v === 'string' && v.length > 0 && v.length <= VOICE_MSG_MAX_B64
  && /^[A-Za-z0-9+/=]+$/.test(v);
const isVoiceMime = (v) => VOICE_MSG_MIMES.includes(v);
```

C2S 表（放在 `'g.emote'` 之后）：

```js
  'g.voice': { data: isVoiceData, ms: (v) => isInt(v, VOICE_MSG_MIN_MS, VOICE_MSG_MAX_MS), mime: isVoiceMime },
```

S2C 白名单数组加 `'m.voice'`（紧挨 `'m.emote'`）。

> `mime` **必须随消息一起传**：录制端和播放端可能不是同一种浏览器，接收方需要知道怎么解。

### 2.3 `server/match/match/intents.js`

在 `emote()`（第 52 行）之后加：

```js
  /** 对局内语音消息: relay a short clip to the room (no state, no replay — like an emote). */
  voice(ps, data, ms, mime) {
    if (typeof data !== 'string' || data.length > VOICE_MSG_MAX_B64) return fail(ERR.BAD_MSG, 'voice too long');
    if (!VOICE_MSG_MIMES.includes(mime)) return fail(ERR.BAD_MSG, 'voice mime');
    const now = this.sched.now();
    if (now - ps.lastVoiceAt < VOICE_MSG_COOLDOWN_MS) return fail(ERR.RATE);
    ps.lastVoiceAt = now;
    this.broadcast({ t: 'm.voice', playerId: ps.playerId, data, ms, mime });
    return OK;
  }
```

在 `switch (msg.t)` 里加 `case 'g.voice': return this.voice(ps, msg.data, msg.ms, msg.mime);`
（`g.emote` 的 case 就在同一处）。

`server/match/PlayerState.js` 里照 `this.lastEmoteAt = -Infinity;` 加 `this.lastVoiceAt = -Infinity;`。

> 若也要在**房间等待阶段**可用，另需在 `server/lobby.js` 的 `onMessage` 加一条分支并广播；
> 本方案只做对局内，可省掉这一半工作量。

### 2.4 `public/js/ui/voice.js`（新增）

```js
// 对局内语音消息 (remake option): record a short clip, send it as base64, play what arrives.
import { VOICE_MSG_MAX_MS, VOICE_MSG_MIN_MS } from '../../../shared/constants.js';

const pickMime = () => {
  for (const m of ['audio/webm;codecs=opus', 'audio/webm', 'audio/mp4', 'audio/ogg']) {
    if (globalThis.MediaRecorder?.isTypeSupported?.(m)) return m;
  }
  return ''; // let the browser choose: Chrome/Firefox → webm/opus, iOS Safari → mp4/AAC
};

/** Start recording. Returns { stop, cancel } — `stop` resolves { data, ms, mime } or null. */
export async function startRecording(onTooLong = null) {
  const stream = await navigator.mediaDevices.getUserMedia({
    audio: { echoCancellation: true, noiseSuppression: true, autoGainControl: true },
  });
  const mime = pickMime();
  const rec = new MediaRecorder(stream, mime ? { mimeType: mime, audioBitsPerSecond: 24000 } : { audioBitsPerSecond: 24000 });
  const chunks = [];
  const t0 = Date.now();
  rec.ondataavailable = (e) => { if (e.data && e.data.size) chunks.push(e.data); };
  const done = new Promise((resolve) => {
    rec.onstop = async () => {
      for (const t of stream.getTracks()) t.stop();
      const ms = Date.now() - t0;
      if (ms < VOICE_MSG_MIN_MS || !chunks.length) return resolve(null);
      resolve({ data: await blobToB64(new Blob(chunks, { type: chunks[0].type || mime || 'audio/webm' })), ms, mime: baseMime(chunks[0]?.type || mime) });
    };
  });
  rec.start();
  // hard cap: a clip the server would refuse is not worth sending
  const timer = setTimeout(() => { onTooLong?.(); if (rec.state !== 'inactive') rec.stop(); }, VOICE_MSG_MAX_MS);
  return {
    stop: () => { clearTimeout(timer); if (rec.state !== 'inactive') rec.stop(); return done; },
    cancel: () => { clearTimeout(timer); chunks.length = 0; if (rec.state !== 'inactive') rec.stop(); return done; },
  };
}

/** `audio/webm;codecs=opus` → `audio/webm` (one of VOICE_MSG_MIMES, which the server whitelists). */
const baseMime = (m) => String(m || '').split(';')[0].trim() || 'audio/webm';

function blobToB64(blob) {
  return new Promise((resolve, reject) => {
    const fr = new FileReader();
    fr.onload = () => resolve(String(fr.result).split(',')[1] || '');
    fr.onerror = () => reject(fr.error);
    fr.readAsDataURL(blob);
  });
}

/**
 * Play a received clip. Uses a plain <audio> element on purpose: it does not touch audio.js internals
 * (its sfx() only plays manifest presets) and works with the mp4 iOS produces.
 * `volume` should come from the player settings (`voice`); `muted` must be honoured.
 */
export function playVoice(b64, mime, { volume = 1, muted = false } = {}) {
  if (muted || !b64) return;
  try {
    const bin = atob(b64);
    const u8 = new Uint8Array(bin.length);
    for (let i = 0; i < bin.length; i++) u8[i] = bin.charCodeAt(i);
    const url = URL.createObjectURL(new Blob([u8], { type: mime || 'audio/webm' }));
    const el = new Audio(url);
    el.volume = Math.max(0, Math.min(1, volume));
    el.onended = () => URL.revokeObjectURL(url);
    el.onerror = () => URL.revokeObjectURL(url);
    el.play().catch(() => {}); // iOS may block without a gesture: fail silently, the bubble stays clickable
    return el;
  } catch { return null; }
}
```

## 3. 必须处理的 7 个坑

1. **64 KB 载荷上限**（`websocket.js:16`）。8 秒方案安全；改时长必须同步改常量，否则连接被拒。
2. **服务器拒绝二进制帧**（`net.js:589`）。只能 base64，别去改 `onFrame`。
3. **iOS 格式不同**：Chrome/Firefox 出 `audio/webm;codecs=opus`，iOS Safari 出 `audio/mp4`（AAC）。
   不要硬指定 mimeType，且**必须把 mime 随消息发送**，否则跨端播放不出来。
4. **iOS 自动播放限制**：收到他人语音时可能没有用户手势，`el.play()` 会被拒绝。
   必须 `.catch()` 静默失败，并让气泡可点击重播（点击即手势，就能播）。
   BGM 已在跑说明 AudioContext 解锁这条路是通的，但 `<audio>` 是另一条路径，仍要兜底。
5. **麦克风权限**：`getUserMedia` 需要 HTTPS（已有）且需用户授权。被拒时隐藏按钮 + 一次提示，不要反复弹。
6. **命名冲突**：`audio.js` 已有 `VOICE_COOLDOWN_MS`，新常量一律用 `VOICE_MSG_*`。
7. **观战者也会收到**：`this.broadcast()` 发给房间里所有人（含观战者）。
   若要排除，需改用 `send` 逐个发给非观战座位；建议**先保留**（观战者听语音合理）。

补充注意：语音是瞬时消息，**不要**进断线重连的 resync（不像 `m.public`），否则重连会突然播一堆旧语音。

## 4. 验证方法

1. **端到端脚本**：照此前「阵营许愿」的做法，写一个 ws 脚本连 `ws://127.0.0.1:3000/ws`，
   建房 → 发 `g.voice`（塞一段合法 base64）→ 断言收到 `m.voice`，
   再分别测：超长（>40 KB 应 `BAD_MSG`）、冷却内连发（第二次应 `RATE`）、非法 mime（应 `BAD_MSG`）。
2. **边界**：构造正好 8 秒 / 略超 8 秒的片段，确认客户端会自动截断且不触发服务端拒绝。
3. **真机矩阵（必做）**：iPhone Safari ↔ iPad Safari ↔ PC Chrome 互发，验证 iOS 出的 mp4 在 Chrome 能播、
   Chrome 出的 webm 在 iOS 能播。这是本方案唯一的真实风险点。
4. **带宽**：4 人房间连发 10 条，观察服务器带宽与游戏帧率有无明显劣化。

## 6. 部署与后续升级

本方案改动的 `shared/`、`server/`、`public/js/` 全在 `MANIFEST.json` 校验范围内，与「阵营许愿」同级。

已有设施：
- `/opt/stronghold/custom/wish.patch` — 许愿补丁
- `/opt/stronghold/custom/apply-wish.sh` — 重打脚本
- `/opt/stronghold/custom/base/` — 6 个官方原文件备份

**建议**：语音做完后把两者的改动合并进同一个 patch（或新增 `voice.patch` + 扩展 `apply-wish.sh` 为
`apply-custom.sh` 依次应用），避免两个补丁互相打架。

升级顺序与许愿完全一致，**顺序反了会 fatal 拒绝启动**：

1. 解压官方 update 包
2. **先启动一次**（让它消耗 `UPDATE.json` 完成校验）
3. 停服 → 跑定制脚本重打补丁 → 再启动

> 原理：`server/update.js` 的 `applyUpdate()` 在 `UPDATE.json` 不存在时第一行就 `return { state: 'none' }`，
> 所以**平时启动根本不校验**，改源码后日常重启毫无影响；只有解压 update 包时才全量校验。
